## I — 方法论骨架 (Interpretation)

本卡不是独立方法论，是一组查表口径，用于把本集的年号纪年与公元年互查，防止时间轴错位。

原文给出两个锚点：隆庆六年 = 公元 1572 年（万历登基）；万历十年 = 公元 1582 年（张居正去世）。

由锚点推出公式：万历 N 年 = 1572 + N。代入 N=1 得万历元年 = 1573，与史实一致；注意登基当年是隆庆六年，不是万历元年。

严格纪律：公式只适用于万历年间；原文未给对应公元年的年份（如弘治十五年）不得自行倒推，只能标注"原文未给"。

## E — 可执行步骤 (Execution)（查表流程）

**必需输入**: 待换算的年号年份（年号 + N，如"万历八年"）。只给"N 年"没给年号时先问清年号，不能默认套万历公式。

**交付物与完成标准**: 对照表（年号年份/公元年/来源标签：原文锚点|公式推导|不可换算）+ 验证行。整数年，无小数、无舍入容差。

1. **找锚点**：确认原文给出的年号—公元对应（本卡：隆庆六年=1572、万历十年=1582）。
   - 完成标准: 至少一个锚点在手；一个都没有则停止。
   - 判停条件: 待换算年份不属于万历年间 → 停止，输出"公式不适用"，不得用 1572+N 套其他年号。
2. **套公式**：万历 N 年 = 1572 + N。
   - 完成标准: 写出 N 与 1572+N 的计算式。
3. **回验**：用另一锚点验证（万历十年：1572+10=1582 ✓）。
   - 完成标准: 计算结果与原文两个锚点均无冲突。
4. **输出并标注来源**：原文直接给出的标"原文锚点"；公式算出的标"公式推导"；原文未给且公式覆盖不到的标"不可换算，不得倒推"（如弘治十五年）。
   - 完成标准: 每个年份都带来源标签。

常见坑：① 把不同年号的年份混进同一公式（弘治十五年 ≠ 1572+15）；② 万历元年 = 1573 而非 1572——登基当年（隆庆六年）不是万历元年；③ ASR 残留（"万利""洪治"）先归一为万历/弘治再查；④ 改元跨年、干支纪日等细节本卡不覆盖，需外部核对。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 换算万历以外的年号（弘治、嘉靖、隆庆 N≠6 等）: 公式不适用，原文未给的不得倒推。
- 涉及改元月份、跨年细节、干支纪日的精确考证: 本卡只有整数年口径。
- 需要权威历史纪年数据: 本卡口径来自本集转写稿，用于本集内部时间轴一致性，不是学术纪年表。

### 作者在书中警告的失败模式

- 原文"洪治15年"给了年号却未给公元年——示范了"给年号不给公元"的陷阱；提取侧已标注不得自行倒推，这是本卡必须保留的纪律。

### 作者的盲点 / 时代局限

- 阶段 0 批判：本集数据均未逐条注出处页码，两个锚点本身也是转述；对外引证前需外部核对（如《明史》）。

### 容易混淆的邻近方法论

- p05 提前量检查（半个时辰=1小时）；f03 前后对比三线评估（只借用年份，不做纪年换算）。
